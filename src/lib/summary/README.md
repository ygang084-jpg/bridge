# 자동 요약 파이프라인

교량 상세 최상단의 한 문장 요약을 **미리 만들어 `bridge_summaries` 에 저장**하는 코드다.
AI API를 쓰지 않는다. 공식 정보의 값을 정해진 문장 틀에 끼워 만든다.

```
스케줄러(Vercel Cron)
  └─ 원본 갱신 (bridges / bridge_history)   ← 아직 구현 안 됨
       └─ job.js  runSummaryRefreshJob()
            ├─ summariesRepo.js  loadSummaryInputs()      원본 읽기
            ├─ buildSummary.js   generateSummary()        문장 + based_on 만들기
            │    └─ validateSummary.js                   금지표현 / 60자 / 근거 없는 숫자
            └─ refreshSummaries.js                       변경 없으면 건너뛰고, 바뀐 것만 저장
```

교량 상세 화면은 이 파이프라인을 부르지 않는다. `bridge_summaries.summary_text` 를 읽기만 한다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `safetyGrades.js` | 안전등급 코드 → 법정 정의 문구 매핑표. **요약에는 쓰지 않는다** (아래 참고) |
| `forbiddenPhrases.js` | 판정·행동 지시·등급 반복·추정 표현 패턴 목록 |
| `validateSummary.js` | 저장 전 3가지 검사 |
| `buildSummary.js` | 문장 조립 + `based_on` 생성 |
| `refreshSummaries.js` | 재생성 판단, 순차 처리, 저장 |
| `summariesRepo.js` | Supabase 읽기·쓰기 |
| `job.js` | 스케줄러가 부르는 진입점 |

## 문장 틀

```
"1917년에 지어졌고, 최근 점검은 9개월 전인 2025년 11월, 마지막 보수는 2016년 5월입니다."  (58자)
 └─ 준공 ─┘        └─ 경과 + 점검 연·월 ─┘        └─ 보수 연·월 ─┘
```

- 값이 없는 절은 통째로 뺀다. 추정해서 채우지 않는다 (PRD F-02 ⑤).
- 절이 0개면 문장을 만들지 않고 `null` 을 저장한다 (F-05).
- **준공연도는 혼자 나오지 않는다.** 항상 점검·보수와 함께 나온다 (F-02 ③).
  준공 연수를 크게 강조하지 않는 이유는 PRD §1 그대로다 — 연수만 보여주면
  '오래됨 = 위험함'이라는 오해를 문장이 스스로 만든다.
- 안전등급은 문장에 넣지 않는다. 등급은 관리 이력의 해당 시점에 놓인다 (F-02.1).

### 60자를 넘을 때 덜어내는 순서

문장을 자르지 않는다. 덜 중요한 절을 정해진 순서로 빼고 다시 조립한다.

| 단계 | 조합 |
| --- | --- |
| 0 | 준공 + 점검(경과 포함) + 보수 |
| 1 | 준공 + 점검(경과 없이) + 보수 |
| 2 | 준공 + 점검(경과 포함) |
| 3 | 준공 + 점검(경과 없이) |

어느 단계를 썼는지는 `based_on.assembled_step` 에 남는다. 4단계까지 줄여도 60자를
넘으면 가장 짧은 후보를 그대로 검증에 넘겨 **저장하지 않는다** — 조용히 잘라내면
문장이 잘린 채로 저장된다. 보수 절을 뺀 경우에도 상세 화면 '관리 요약'에는 마지막
보수 시점이 그대로 남아 있으므로 정보가 사라지지는 않는다.

## 저장 전 검사 3가지

1. **금지 표현** — 판정(안전하다/위험하다/괜찮다/주의가 필요하다), 행동 지시(건너도 된다/우회하세요),
   등급 반복(안전등급 B입니다), 추정(가능성/것으로 보인다).
   등급 이름(우수·양호·보통·미흡·불량)도 막는다 — 그 자체가 판정어다.
2. **60자 초과**
3. **근거 없는 숫자** — 문장에 등장하는 모든 숫자가 `based_on.allowed_numbers` 안에 있어야 한다.
   허용되는 건 원본 값(준공연도, 점검·보수 연·월)과 그 값에서 정해진 계산으로 나온 값(경과 기간)뿐이다.

하나라도 걸리면 저장하지 않고 `summary_text = null`, 걸린 이유는 `based_on.rejected_by` 에 남긴다.

**재시도는 두지 않았다.** 같은 입력에 같은 문장이 나오는 결정적 생성이라 다시 돌려도 결과가 같다.
재시도하는 흉내를 내면 템플릿 버그를 가리게 된다. (AI 호출 방식이었다면 1회 재시도가 의미 있었을 자리다.)

## 재생성 판단

`based_on` 에서 `template_version` / `source` / `derived` / `omitted` 를 뽑아 지문을 만들고,
저장된 것과 같으면 건너뛴다.

- `reference_date` 는 지문에서 뺐다 — 넣으면 날마다 달라져 매일 재생성한다.
- `derived`(경과 기간)는 **넣었다.** 원본이 그대로여도 시간이 흐르면 "9개월 전"이
  "10개월 전"으로 틀려진다. 원본만 비교하면 문장이 조용히 사실과 어긋난 채 남는다.
  그래서 "원본이 바뀌지 않았으면 재생성하지 않는다"를
  **"원본과, 원본에서 계산한 값이 모두 그대로면 재생성하지 않는다"** 로 읽었다.
  규칙 기반이라 재생성 비용이 0이므로 이 쪽이 안전하다.

## 안전등급을 요약에 쓰지 않는 이유

`safetyGrades.js` 는 등급 코드 → 법정 정의 매핑표를 갖고 있지만 요약 생성기는 이것을 쓰지 않는다.
정의 문구를 요약에 넣으면 "양호한 상태입니다" 같은 판정 표현이 되고, 등급을 되풀이하는 것이 되어
5단계 워크시트가 정한 요약의 목적에 어긋난다. 등급은 `based_on` 에 기록해 두기만 한다 —
나중에 요약과 원문을 대조할 때 필요하기 때문이다.

매핑표는 **관리 이력 타임라인의 해당 시점에 펼쳐 쓰는 등급 정의**용이다.
PRD F-02.1 이 툴팁·아코디언처럼 추가 조작이 필요한 방식을 금지했으므로 툴팁으로 쓰지 않는다.
`SAFETY_GRADE_SOURCE.url` 과 `verifiedOn` 이 비어 있는 동안은 화면에 표시하지 않는다 —
6단계 데이터설계가 `risk_thresholds` 에 적용한 "출처가 비면 표시하지 않는다" 원칙과 같다.

## 확인 스크립트

```bash
node scripts/check-summaries.mjs                    # 표본 3곳
node scripts/check-summaries.mjs --date=2026-08-18  # 기준일 고정 (결과 재현)
node scripts/check-summaries.mjs --db               # Supabase 원본 3곳
```

## 환경변수

`.env.local` (git 에 올라가지 않음). `.env.example` 참고.

```
SUPABASE_URL=...
SUPABASE_SERVICE_ROLE_KEY=...
```

서비스 롤 키를 `VITE_` / `PUBLIC_` / `NEXT_PUBLIC_` 접두사로 두면 `serverClient.js` 가 즉시 던진다.
그 접두사가 붙은 값은 번들에 그대로 박혀 브라우저까지 나가기 때문이다. 조용히 동작하다
배포 번들에 키가 실려 나가는 쪽이 예외로 멈추는 쪽보다 훨씬 위험하다.
